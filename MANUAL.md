# Протокол: Бункер — руководство пользователя (Windows)

Ниже — единый, понятный мануал: установка, запуск, конфиги, self‑host.

## 1) Что нужно заранее

- Windows 10/11
- Linux
- macOS
- Node.js LTS (рекомендуется 20.x)
- pnpm (или corepack)

Примечание: Windows‑ и Linux‑скрипты при запуске сами проверяют Node.js и pnpm и предложат установить, если чего‑то нет.  
macOS тоже поддерживается (через `brew`), но авто‑настройка reverse‑proxy сейчас включена только для Linux.
Скрипты также автоматически выполняют `pnpm install`.

---

## 2) Запуск

### 2.1 Dev (для разработки)

Запуск:
```
run-dev.bat
```

Откроется локальный сайт по адресу:
```
http://localhost:5173
```

Сервер dev‑режима слушает:
```
http://localhost:3001
```

Примечание: в dev‑режиме каждая вкладка браузера считается новым игроком.

### 2.2 Self‑host (prod‑режим)

**Prod‑режим** — это стабильный режим для реальной игры: без dev‑особенностей, с нормальным переподключением по токену.

Запуск:
```
run-selfhost.bat
```

Сценарий запуска:
1) «Local (no HTTPS)» — локальная развёртка сервера без HTTPS (LAN/интернет по IP:PORT)
2) «Domain (HTTPS)» — сайт на существующем домене через reverse‑proxy (HTTPS/WSS)

По умолчанию сервер слушает:
```
http://0.0.0.0:3000
```

## 3) Как открыть игру с другого устройства

### Вариант A — LAN/интернет по IP

После запуска self‑host скрипт покажет ссылки:
- Public: `http://<внешний_IP>:3000` — для доступа из интернета (после проброса порта на роутере)
- Local:  `http://<локальный_IP>:3000` — для устройств в вашей локальной сети

Для доступа из интернета нужно пробросить порт в роутере:
- TCP порт 3000 → на локальный IP компьютера

Если используешь другой порт — пробрасывай его.

### Вариант B — домен и HTTPS

1) Запусти `run-selfhost.bat` и выбери «Domain».
2) Настрой reverse‑proxy (Caddy/Nginx) на сервере с доменом.

Пример Caddyfile:
```
<domain> {
  reverse_proxy localhost:3000
}
```

### Авто‑настройка reverse‑proxy (Linux)

Для Linux добавлен автоскрипт проверки/настройки (только при выборе Domain):

- проверяет порт 443
- проверяет установлен ли Caddy/Nginx
- предлагает установить Caddy, если ничего нет
- пишет корректные конфиги с учётом выбранного `PORT`

При первом запуске скрипт спросит, включать ли авто‑проверки.
Если согласиться — они будут выполняться при каждом запуске.
Если отказаться — сервер просто стартует.

Как отключить автопроверку:

```
rm .selfhost/proxy-auto
touch .selfhost/proxy-auto-disabled
```

Как включить обратно:

```
rm .selfhost/proxy-auto-disabled
```

После этого вход будет:
```
https://<domain>
```

## 4) Конфигурации (ENV)

Проект читает переменные окружения. Пример лежит в корне:
- `.env.example`

### Важные переменные сервера

- `HOST` — интерфейс (default: `0.0.0.0`)
- `PORT` — порт сервера (default: `3000`)
- `TRUST_PROXY` — `true`, если сервер за reverse‑proxy
- `PUBLIC_ORIGIN` — опционально (только для логов)
- `BUNKER_IDENTITY_MODE` — `prod` или `dev_tab`
- `BUNKER_ASSETS_ROOT` — опционально: путь до `assets`
- `BUNKER_CLIENT_DIST` — опционально: путь до `client/dist`

### Важные переменные клиента

- `VITE_WS_URL` — явный WS‑адрес (если пусто — берётся от origin)
- `VITE_API_BASE` — явный HTTP API (если пусто — берётся от origin)
- `VITE_ASSET_BASE` — явный адрес ассетов (если пусто — берётся от origin)
- `VITE_IDENTITY_MODE` — `prod` или `dev_tab`

### Правило по режимам

- Dev‑скрипты принудительно ставят `dev_tab`.
- Self‑host скрипт принудительно ставит `prod`.

Если хочешь менять поведение вручную — редактируй `.env`.

### Optional path overrides (пример)

Без env (по умолчанию):
```
# ничего не задавать
```

С переопределением путей:
```
BUNKER_ASSETS_ROOT=D:/Games/Bunker/assets
BUNKER_CLIENT_DIST=D:/Games/Bunker/client/dist
```

## 6) Частые вопросы

### Порт занят
Если self‑host пишет “Port 3000 is already in use”:
1) Закрой старый сервер (окно консоли) или
2) Убей процесс:
```
netstat -ano | findstr :3000
taskkill /PID <PID> /F
```

### В консоли видно TIME_WAIT
Это нормально: соединение уже закрыто, порт свободен.
Смотри только `LISTENING`.
