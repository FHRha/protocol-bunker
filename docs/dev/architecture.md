# Архитектура проекта

Protocol: Bunker организован как монорепозиторий. Основные части проекта разделены по ответственности: клиент, сервер, общие контракты, сценарии, тесты, служебные скрипты и документация.

## Общая схема

В упрощённом виде структура проекта выглядит так:

- `client` — браузерный интерфейс игры;
- `server` — серверная логика, комнаты, подключения и состояние матча;
- `shared` — общие типы, контракты и структуры данных;
- `scenarios` — сценарии, карты и игровой контент;
- `tests` — автоматические проверки;
- `scripts` — сборка, упаковка и служебные процессы;
- `docs` — документация проекта.

## Основные части проекта

### `client`

`client` отвечает за браузерную часть проекта.

Здесь находится:
- интерфейс входа, лобби и игровой комнаты;
- отображение игроков, карточек, голосований и статусов;
- режимы для ведущего, зрителей и стриминга;
- локализация интерфейса;
- адаптивное и мобильное поведение;
- визуальная логика клиентской части.

### `server`

`server` отвечает за серверную сторону игры.

Здесь находится:
- создание и жизненный цикл комнат;
- подключения клиентов;
- серверное состояние матча;
- обработка websocket-событий;
- игровые действия и синхронизация состояния;
- логика ролей хоста, игроков, зрителей и служебных соединений.

### `shared`

`shared` содержит общие типы и контракты между клиентом и сервером.

Здесь находится:
- типизация сообщений и событий;
- payload’ы;
- общие доменные сущности;
- перечисления, структуры данных и контракты;
- общие утилиты без привязки к конкретной стороне приложения.

### `scenarios`

`scenarios` отвечает за сценарии и игровой контент.

Здесь находится:
- сценарии;
- наборы карт;
- структурированные игровые данные;
- special conditions;
- контентные сущности, загружаемые во время игры.

## Остальные директории

### `tests`

`tests` содержит автоматические проверки проекта, включая критичные интеграционные сценарии и проверки сетевого поведения.

### `scripts`

`scripts` содержит вспомогательные скрипты для сборки, упаковки, подготовки релизов и других служебных процессов.

### `docs`

`docs` содержит документацию проекта и разделён по аудиториям:
- `docs/user/`
- `docs/host/`
- `docs/streaming/`
- `docs/dev/`
- `docs/internal/`

## Связи между частями проекта

В упрощённом виде зависимости выглядят так:

- `client` работает с сервером через общие контракты из `shared`;
- `server` использует `shared` и работает со сценарными данными из `scenarios`;
- `scenarios` поставляет игровой контент;
- `tests` проверяет совместную работу основных частей;
- `scripts` собирает и упаковывает итоговые артефакты;
- `docs` описывает структуру, запуск и использование проекта.
