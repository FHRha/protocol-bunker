# Настройка ботов и AI

Этот документ описывает, как работают игровые боты, как ограничен доступ к AI-ботам и как настроить OpenAI-compatible gateway.

## Режимы ботов

В настройках лобби доступны три практических режима:

- боты выключены;
- обычные rule-based боты;
- AI-боты.

Хост выбирает тип ботов и их количество в лобби. Текст обычных ботов следует локали UI/сервера каждого игрока. Язык ответа AI-бота — общий параметр лобби, потому что один и тот же ответ видят все игроки.

## Обычные rule-based боты

Обычные боты не вызывают LLM. Они работают на сервере и используют только видимое состояние игры.

Текущее поведение:

- имена ботов генерируются из ключей локализации;
- боты ждут перед действием, а не переключают ход мгновенно;
- решение о раскрытии карты строится на лёгкой оценке;
- после раскрытия карты бот пишет короткое локализованное объяснение;
- во время обсуждения бот может продолжить раунд, когда его раскрытие завершено;
- во время голосования бот выбирает видимую допустимую цель;
- реплики ботов попадают в историю сообщений матча и могут отображаться как speech bubble рядом с местом бота.

Оценка для раскрытия карты намеренно простая:

- начинается со статического приоритета колоды из `server/src/bots/ruleBasedConfig.ts`;
- добавляются небольшие бонусы по ключевым словам катастрофы/мира, например эпидемия, война, холод, жара, наводнение, нехватка еды или социальный коллапс;
- добавляется дешёвое пересечение ключевых слов между видимым текстом мира и названиями или id карт;
- выбирается самая высокооценённая нераскрытая карта.

Так обычные боты остаются быстрыми, тестируемыми и объяснимыми без semantic search или вызовов модели.

Задержка управляется параметрами:

```env
BUNKER_RULE_BOT_MIN_DELAY_MS=1200
BUNKER_RULE_BOT_MAX_DELAY_MS=2600
```

## AI-боты

AI-боты вызывают OpenAI-compatible endpoint `/chat/completions`. Сервер не позволит начать игру с AI-ботами, если:

- не настроен AI gateway;
- хост не валидировал AI access key.

Промпт для AI отправляется только тогда, когда боту нужно сделать осмысленный выбор:

- фаза раскрытия: выбрать, какую карту раскрыть, и объяснить почему;
- фаза голосования: выбрать допустимую цель и объяснить почему.

Продолжение раунда после раскрытия обрабатывается сервером после обычной задержки бота. Модель для этого не вызывается.

В AI-промпте передаётся только видимое состояние бота:

- текущая фаза и раунд;
- текущий ход;
- видимые карты катастрофы, угроз и бункера;
- рука самого бота;
- видимые карты игроков;
- допустимые ограничения для голосования.

Скрытые карты и серверное состояние в модель не отправляются.

Промпт жёстко требует JSON-ответ:

```json
{
  "action": "revealCard|vote",
  "cardInstanceId": "...",
  "targetPlayerId": "...",
  "explanation": "short human-like reason"
}
```

Системное правило:

```text
Return valid JSON only. Never reveal hidden information.
```

Правила пользовательского промпта:

- действуй как AI-игрок в Bunker;
- используй только видимое JSON-состояние;
- не придумывай скрытые карты или секретную информацию;
- пиши объяснение на языке AI, выбранном в лобби;
- выбирай ровно одно допустимое действие;
- никогда не выбирай `continueRound`, потому что продолжение раунда делает сервер.

Если gateway падает или возвращает невалидное действие, сервер переходит на допустимое детерминированное действие, чтобы матч мог продолжиться.

## Настройка gateway

Пример значений `.env`:

```env
BUNKER_AI_GATEWAY_BASE_URL=https://api.openai.com/v1
BUNKER_AI_GATEWAY_API_KEY=sk-...
BUNKER_AI_GATEWAY_MODEL=gpt-4o-mini
BUNKER_AI_GATEWAY_TIMEOUT_MS=45000
```

Gateway работает только на сервере. Не передавайте gateway API key в клиент.

## AI access keys

Доступ к AI-ботам ограничивается серверными access keys. Хост вводит ключ в настройках клиента; клиент валидирует его через сервер и затем отправляет только состояние доступа через private websocket message. Сам ключ не хранится в broadcast room settings.

Файл хранилища по умолчанию:

```env
BUNKER_AI_ACCESS_KEYS_FILE=data/ai-access-keys.json
```

Команды для управления ключами:

```bash
pnpm -C server ai:key:create -- --label "Host name"
pnpm -C server ai:key:list
pnpm -C server ai:key:edit -- <id> --label "New label"
pnpm -C server ai:key:validate -- <key>
pnpm -C server ai:key:revoke -- <id>
pnpm -C server ai:key:delete -- <id>
```

В релизной версии те же команды доступны через `protocol-bunker`:

```bash
protocol-bunker ai:key:create --label "Host name"
protocol-bunker ai:key:list
protocol-bunker ai:key:edit <id> --label "New label"
protocol-bunker ai:key:validate <key>
protocol-bunker ai:key:revoke <id>
protocol-bunker ai:key:delete <id>
```

Заметки по безопасности:

- сырой сгенерированный ключ показывается только один раз;
- сохранённые ключи хэшируются;
- скомпрометированные ключи нужно отзывать или удалять;
- доступ к AI проверяется на сервере, а не через UI клиента.

## Текущие ограничения

- выбор persona для AI пока не реализован;
- память AI на матч пока ограничена только видимым состоянием из каждого запроса;
- квоты токенов и учёт использования пока не реализованы;
- retry/backoff поведение всё ещё базовое;
- mobile chat layout отложен до стабилизации desktop flow.
