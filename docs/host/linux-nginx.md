# Linux + nginx

Этот файл — практический гайд для Linux-сценария, где Protocol: Bunker запускается в `server`-профиле и отдаётся наружу через домен и nginx.

Этот вариант нужен, если ты хочешь:
- поднять игру на Linux-сервере;
- использовать домен;
- работать через `HTTPS`;
- скрыть LAN / localhost-ссылки;
- получить более нормальный серверный сценарий для внешних игроков.

## Что здесь предполагается

В этом сценарии:
- игра работает в `server`-профиле;
- само приложение слушает локальный порт;
- наружу доступ идёт через nginx;
- игроки заходят по домену;
- websocket тоже должен работать через прокси.

## Самый короткий путь

Если нужен быстрый серверный Linux-сценарий, обычно порядок такой:

1. Установить игру через `install.sh` в `server`-профиле.
2. Настроить `portable.env`.
3. Поднять nginx.
4. Настроить домен и reverse proxy.
5. Перезапустить сервис.
6. Проверить, что открывается сайт и работает подключение к комнате.

---

## Установка server-профиля

Самый простой вариант:

`curl -fsSL https://raw.githubusercontent.com/FHRha/protocol-bunker/main/install.sh | bash -s -- --edition server`

Если нужен `ARM64`:

`curl -fsSL https://raw.githubusercontent.com/FHRha/protocol-bunker/main/install.sh | bash -s -- --edition server --arch arm64`

Если нужен автозапуск сразу при установке:

`curl -fsSL https://raw.githubusercontent.com/FHRha/protocol-bunker/main/install.sh | bash -s -- --edition server --service-scope system --autostart`

## Что даёт server-профиль

`server`-профиль:
- скрывает LAN / localhost-ссылки в launcher;
- скрывает LAN / localhost-ссылки в блоке ссылок в лобби;
- лучше подходит для удалённого сервера и внешнего доступа.

## Где лежат настройки

Обычно настройки редактируются здесь:

`nano ~/.local/share/protocol-bunker/Protocol-Bunker/portable.env`

---

## Базовая настройка для домена

Если игра будет открываться по домену, поставь минимум:

`PORT=8080`
`DEV_MODE=0`
`MODE=domain`
`DOMAIN=your.domain.com`

Заменяй `your.domain.com` на свой реальный домен.

## Если нужен локальный режим с явным внешним адресом

Можно использовать:

`PORT=0`
`DEV_MODE=0`
`MODE=local`

И при необходимости явно задать внешний адрес:

`PUBLIC_HOST=203.0.113.10`

или

`PUBLIC_ORIGIN=http://203.0.113.10:8080`

Если `PUBLIC_HOST` / `PUBLIC_ORIGIN` не заданы, внешний адрес определяется автоматически через внешние сервисы.

## Важно про `PUBLIC_ORIGIN`

- можно указывать `https://your.domain.com`;
- порт указывай только если внешний доступ реально идёт на нестандартный порт, например `:8443`;
- если домен работает через reverse proxy на обычном `443`, порт в `PUBLIC_ORIGIN` обычно не нужен.

---

## Какой порт использует приложение

В типичном сценарии:
- приложение слушает `127.0.0.1:8080`;
- nginx принимает внешний трафик на `80/443`;
- дальше nginx проксирует запросы к приложению.

То есть само приложение наружу можно не открывать напрямую.

---

## Что должно быть настроено в nginx

nginx должен:
- отдавать основной HTTP / HTTPS-трафик;
- проксировать websocket;
- передавать нужные заголовки;
- работать с твоим доменом.

## Минимальная логика reverse proxy

В общем виде nginx должен проксировать запросы на локальный порт приложения, например:

- внешний домен → nginx
- nginx → `127.0.0.1:8080`

При этом для websocket должны быть корректно переданы upgrade-заголовки.

То есть важно не только чтобы открывалась страница, но и чтобы жило соединение игры.

---

## Что важно для websocket

Очень частая ошибка: сайт открывается, а подключение к комнате не работает.

Обычно это значит, что:
- websocket не проксируется;
- не переданы upgrade-заголовки;
- прокси настроен только под обычный HTTP;
- наружу отдан не тот origin / домен.

Если интерфейс грузится, но игроки не могут нормально подключиться — в первую очередь смотри именно в эту сторону.

## После изменения настроек

Если ты изменил `portable.env`, перезапусти сервис:

`sudo systemctl restart protocol-bunker`

Проверить статус:

`sudo systemctl status protocol-bunker`

Посмотреть логи:

`sudo journalctl -u protocol-bunker -f`

---

## Полезные команды сервиса

Остановить:

`sudo systemctl stop protocol-bunker`

Запустить:

`sudo systemctl start protocol-bunker`

Перезапустить:

`sudo systemctl restart protocol-bunker`

Статус:

`sudo systemctl status protocol-bunker`

Логи:

`sudo journalctl -u protocol-bunker -f`

---

## Что проверить после настройки

Проверь по порядку:

1. Сервис запущен.
2. Домен открывает страницу игры.
3. Комната создаётся.
4. Игрок по внешней ссылке может зайти.
5. Подключение не ломается сразу.
6. Работает не только страница, но и сама игровая сессия.
7. Если нужен стрим — overlay тоже открывается.

---

## Если сайт открывается, но игра не работает

Проверь:
- правильный ли `DOMAIN` указан в `portable.env`;
- не сломан ли reverse proxy;
- передаётся ли websocket upgrade;
- не упирается ли всё в firewall;
- не смотрит ли nginx не на тот локальный порт;
- не остался ли старый кэш или старый конфиг.

---

## Если нужен HTTPS

Для нормального внешнего доступа через домен HTTPS почти всегда лучше включить.

На практике это значит:
- домен должен смотреть на сервер;
- nginx должен принимать `443`;
- сертификат должен быть настроен корректно;
- приложение должно знать правильный внешний origin.

Если у тебя reverse proxy отдаёт сайт на обычном `443`, то в `PUBLIC_ORIGIN` порт обычно указывать не нужно.

---

## Обновление

Обновить установленную версию:

`protocol-bunker --update`

Или до конкретной версии:

`protocol-bunker --update vX.Y.Z`

После обновления полезно:
1. проверить `portable.env`;
2. перезапустить сервис;
3. открыть сайт;
4. проверить вход в комнату.

`protocol-bunker --update` переустанавливает архив, но сохраняет:
- `portable.env`;
- данные в `app/data`.

## Примечание

Если кратко, рабочая схема для большинства Linux-серверов такая:

1. поставить игру через `install.sh` с `--edition server`;
2. прописать `MODE=domain` и `DOMAIN=...` в `portable.env`;

4. перезапустить сервис;
5. проверить, что работает и страница, и websocket.
