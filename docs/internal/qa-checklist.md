# QA Checklist

Этот файл — внутренний checklist для ручной проверки Protocol: Bunker после заметных изменений, перед релизом или после обновления сборки.

Он не заменяет:
- `docs/dev/testing.md` — общий документ по тестированию;
- автоматические тесты;
- проверки локализации и типов.

Задача этого файла — дать короткий и практичный список того, что стоит проверить руками.

## Когда использовать

Этот checklist особенно полезен:
- перед релизом;
- после изменений в `client`;
- после изменений в `server`;
- после правок websocket-логики;
- после изменений в лобби, комнате, картах и голосовании;
- после изменений в viewer / spectator / control / streamer flow;
- после изменений в релизной упаковке и установке.

## Базовая проверка запуска

Проверь по порядку:

- приложение запускается;
- интерфейс открывается;
- лобби загружается без явных ошибок;
- можно создать комнату;
- ссылка на комнату выглядит корректно;
- второй клиент может зайти в комнату;
- переподключение не ломает состояние сразу.

## Комната и игроки

Проверь:
- хост создаёт комнату без ошибок;
- новый игрок подключается корректно;
- список игроков отображается правильно;
- имена игроков отображаются как ожидается;
- игрок не дублируется в списке;
- выход игрока обрабатывается корректно;
- повторный вход не создаёт “призрачного” игрока.

## Host transfer и роли

Проверь:
- передача роли хоста работает;
- после передачи новый хост реально получает управление;
- старый хост больше не ведёт себя как активный хост;
- служебные соединения не создают лишнего игрока;
- spectator / control flow не ломает состав комнаты;
- выбывший или служебный клиент не становится некорректным “хостом”.

## Игровой сценарий

Проверь:
- игра стартует;
- игрокам раздаются данные;
- сценарий и карты загружаются корректно;
- этапы игры переключаются без поломки состояния;
- открытие карт работает;
- голосование запускается и завершается корректно;
- выбывание обрабатывается нормально;
- после изменений в контенте сценарий не разваливается.

## Карты и контент

Проверь:
- карточки отображаются правильно;
- лицевая и обратная стороны карт не перепутаны;
- нужные типы карт действительно показывают свои данные;
- special conditions работают как ожидается;
- если менялась локализация карт, не происходит неожиданный fallback;
- названия, описания и подписи не съезжают;
- скрытая информация не раскрывается раньше времени.

## Локализация

Проверь:
- UI-строки отображаются на нужном языке;
- новые строки не ушли в пустоту;
- нет очевидного fallback там, где его не должно быть;
- названия карт, сценариев и статусов отображаются корректно;
- интерфейс не показывает сырой ключ вместо нормального текста.

## Лобби и ссылки

Проверь:
- блок ссылок в лобби отображается корректно;
- public / local ссылки ведут туда, куда должны;
- server-профиль не показывает LAN / localhost там, где их быть не должно;
- room-ссылка реально открывает нужную комнату;
- ссылки для стриминга и служебных режимов формируются корректно.

## Mobile / responsive

Если правки затрагивали интерфейс, дополнительно проверь:
- лобби на узком экране;
- комнату на узком экране;
- карточки на мобильной ширине;
- панель действий;
- отсутствие критичных наложений, съехавших блоков и обрезанного текста.

## Streaming / overlay

Если правки затрагивали стримерский сценарий, проверь:
- `overlay` открывается;
- `overlay-control` открывается;
- изменения применяются после `Save`;
- OBS Browser Source показывает актуальное состояние;
- фон и верхние блоки не ломаются;
- игроки и подписи отображаются корректно;
- viewer / control / overlay flow не ломают комнату.

## Установка и обновление

Если правки затрагивали packaging, install или release flow, проверь:
- сборка создаётся;
- артефакт запускается;
- install / portable сценарий не сломан;
- `protocol-bunker --update` работает;
- настройки не теряются после обновления;
- `portable.env` сохраняется;
- сервис после обновления можно перезапустить без ручного ремонта.

## Linux / service / deployment

Если изменения касались Linux-сценария, проверь:
- сервис стартует;
- сервис перезапускается;
- статус сервиса корректный;
- логи не содержат явных критичных ошибок;
- сайт открывается;
- websocket живой;
- после изменения `portable.env` приложение подхватывает нужную конфигурацию.

## Минимальный smoke-check перед релизом

Если нужен совсем короткий обязательный прогон перед релизом, проверь хотя бы это:

1. приложение запускается;
2. создаётся комната;
3. второй игрок заходит;
4. старт игры работает;
5. карточки показываются корректно;
6. голосование работает;
7. host transfer не сломан;
8. overlay-сценарий не сломан, если он затрагивался;
9. релизный артефакт реально запускается.

## После ручной проверки

Если в ходе проверки нашлась проблема, лучше сразу зафиксировать:
- где она проявляется;
- как повторяется;
- это регрессия или старое поведение;
- в каком сценарии она критична.

Для разовых заметок и открытых вопросов лучше использовать `docs/internal/notes/`.

Для технических переносов, переименований и одноразовых переходных вещей лучше использовать `docs/internal/migrations/`.

## Примечание

Этот checklist не обязан быть одинаково длинным для каждого изменения.

Если правка маленькая — достаточно короткого smoke-check.

Если правка затрагивает сетевую логику, роли, упаковку или стримерский сценарий — ручная проверка должна быть заметно шире.
