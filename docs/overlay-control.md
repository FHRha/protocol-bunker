# Overlay Control: руководство

## 1) Что это и как связано с OBS overlay
`/overlay-control` — страница ручного управления текстовыми override для OBS overlay.

- View-страница overlay: `/overlay?room=XXXX&token=VIEW_TOKEN`.
- Страница управления: `/overlay-control?room=XXXX&token=EDIT_OR_HOST_TOKEN`.
- Состояние для control: `GET /overlay-control/state`.
- Сохранение: `POST /overlay-control/save`.

Control работает с тем же `overlayState`, который приходит в overlay-страницу, и рассчитывает **эффективный** вывод так же, как overlay (`applyOverrides`-логика в control повторяет логику рендера overlay).

## 2) Верхние блоки: Бункер / Катастрофа / Угрозы
В секции «Верхние блоки Overlay» есть:

- «Сейчас в OBS ...» — текущее значение, которое реально видит зритель.
- Чекбоксы «Использовать ручной текст ...»:
  - включено: ручной текст может заменять автоматический;
  - выключено: ручной текст для этого блока игнорируется, остаётся авто-текст из игры.
- Поля ручного текста:
  - Бункер: максимум 5 строк, до 120 символов в строке;
  - Катастрофа: до 600 символов;
  - Угрозы: максимум 6 строк, до 120 символов в строке.

Важно для блока «Катастрофа»:
- Базовый текст берётся из данных катастрофы (`world.disaster.text`), если поле заполнено.
- Если `world.disaster.text` пустой, используется старый fallback: `world.disaster.description || world.disaster.title`.
- В UI видно разделение:
  - «Сейчас в OBS: Катастрофа» — effective текст (с учётом override);
  - «Источник из данных катастрофы» — базовый текст из состояния игры;
  - «Сейчас используется: ...» — источник effective текста (авто/override).

Валидация:
- счётчики строк/символов обновляются сразу;
- при превышении лимитов счётчик подсвечивается;
- при `Save` сохранение блокируется с понятной ошибкой.

## 3) Блок игрока
Как работать:

1. Выберите игрока в левом списке или в селекторе.
2. В полях справа редактируйте override только этого игрока.
3. Под каждым полем показано «Сейчас в OBS ...» — текущее реальное значение в overlay output.

Что меняется:

- Имя (`name`).
- Traits (`sex`, `age`, `orient`).
- Категории (`categories[categoryKey]`).
- Тумблеры «Показывать ...» для имени/traits/категорий и для каждой категории.

Тумблеры реально влияют на видимость сегментов в overlay output (не только в локальном UI).

## 4) Save / Reload / несохранённые изменения
- `Save`:
  - валидирует поля;
  - отправляет overrides на сервер;
  - сервер рассылает обновлённый `overlayState` подписчикам.
- `Reload`:
  - заново загружает состояние с сервера;
  - если есть несохранённые изменения, показывает подтверждение.
- Бейдж в хедере:
  - `Синхронизировано` / `Есть несохраненные изменения`.

## 5) Advanced JSON
### Categories JSON (для выбранного игрока)
- Формат: `Record<CategoryKey, string>`.
- Кнопка `Вставить шаблон` вставляет все поддерживаемые category keys.
- Кнопка `Применить JSON` валидирует и переносит значения в форму.

Поведение:
- невалидный JSON: ошибка;
- неизвестные ключи: предупреждение + список разрешённых;
- пустая строка: значение не сохраняется как override;
- отсутствующий ключ: базовое значение overlay не переопределяется.

### ExtraTexts JSON
- Формат: `Array<{ id, text, x, y, align, size, color, shadow, visible }>`.
- Можно редактировать через «человеческую» форму (рекомендуется) или через Advanced JSON.

## 6) Доп. тексты OBS
Секция «Доп. тексты OBS» управляет произвольными подписями поверх overlay:

- текст;
- позиция `x/y` (0..1);
- выравнивание;
- размер;
- цвет;
- видимость;
- тень.

Рекомендация: сначала добавляйте/редактируйте блоки через форму, Advanced JSON используйте для пакетных правок.

## 7) Типичный сценарий
1. Откройте `overlay` в OBS как Browser Source.
2. Откройте `overlay-control` с edit/host токеном.
3. Убедитесь в блоках «Сейчас в OBS ...», что видите актуальные значения.
4. Внесите правки (верхние блоки, игрок, доп. тексты).
5. Нажмите `Save`.
6. Проверьте результат в OBS overlay.
7. Если игроки изменились в лобби, список в control обновится по realtime подписке без перезагрузки страницы.

## 8) Тексты катастроф: где лежат и как добавить
- Файл текстов: `server/data/world/disasters.ru.json`.
- Ключ в JSON: `labelShort` карточки катастрофы (имя файла `.jpg` без расширения).
- Структура записи: `{ title, text, sourceFile, slug }`.

Как добавить новую катастрофу:
1. Добавьте изображение в `assets/decks/Катастрофа/<Название>.jpg`.
2. Добавьте запись с тем же ключом `<Название>` в `server/data/world/disasters.ru.json` и заполните поле `text`.
3. Запустите комнату, откройте overlay/control, проверьте:
   - `Overlay`: блок «Катастрофа» показывает новый текст;
   - `Overlay Control`: в «Источник из данных катастрофы» виден тот же текст.

Кодовая цепочка:
- Индексация карт и `labelShort`: `server/src/catalog.ts`.
- Подстановка текста из JSON в `world.disaster.text`: `scenarios/src/world_deck.ts`.
- Формирование top-блока overlay (приоритет `world.disaster.text`): `server/src/index.ts` (`getOverlayState`).
- Рендер OBS overlay: `server/public/overlay/overlay.js` (`renderTopText` для `top.catastrophe.text`).
- UI Overlay Control (effective/base/source): `server/public/overlay/overlay-control.js` и `server/public/overlay/overlay-control.html`.
